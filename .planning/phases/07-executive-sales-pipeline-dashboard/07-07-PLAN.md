<objective>
Stop the dashboard from double-counting duplicate crm_pipeline rows, and correct the ingestion
documentation that still describes the retired path as live. The loader selects data_source but never
uses it — so a job that exists as both a stale csv_initial row and an api_sync row (e.g. KS-11: a
$0/unassigned api_sync row plus a stale-valued csv_initial row) is counted twice in every KPI. This
plan adds a dedup/precedence step in loadExecutivePipelineDashboard (api_sync wins when both are
present, keyed on acculynx_job_id) so each underlying job contributes exactly once. It also rewrites
sync-pipeline.md to match the live pipeline after the 07-05/07-06 fixes land (capture-first raw
archive, crm_pipeline written on the multiAccount cron, first-sight/change-driven pull, budget
rotation), closing the doc-drift gap the CLAUDE.md "verify against the live DB" lesson exists to
prevent.

Purpose: Closes VERIFICATION gap 8 (uncontrolled duplicates) and gaps 6/9 (doc drift). Runs in the
same wave as 07-06 because it touches disjoint files (dashboard loader + docs vs edge function).
Depends on 07-05 only for the raw-archive concept the docs describe.
Output: a deduped loader + a corrected sync-pipeline.md.
</objective>
