<objective>
Stand up the change-driven trigger layer (D-17): a public-facing Supabase Edge Function that receives
AccuLynx webhook events and turns them into targeted pulls, so steady-state refresh is event-driven
(D-16) rather than a blanket hourly re-pull the rate limits make impossible. Because the webhook
receiver is a NEW public endpoint accepting untrusted external payloads, it verifies authenticity
before acting and treats the body strictly as data (REQ-09 boundary). The AccuLynx webhook auth
mechanism and topic catalog MUST be verified live before design — GET /webhooks/v2/topics with a
subscription is itself a tier-gated WRITE, so the receiver is built and sandbox-proven first, and the
prod subscription (POST /webhooks/v2/subscriptions) is created only after explicit human approval
(the sandbox-prove-then-human-gate write posture, hard rule + D-17).

Purpose: Delivers D-17 (webhooks as triggers) and completes the D-16 change-driven refresh loop the
07-06 job walk implements on the pull side. Depends on 07-05 (raw archive) and 07-06 (first-sight /
targeted pull entry points the receiver enqueues into).
Output: acculynx-webhook Edge Function, an event log table, an OKF webhooks doc, and a human-gated
prod subscription.
</objective>

  <decision>Confirm the live AccuLynx webhook topic catalog and payload-auth mechanism before building the receiver.</decision>
  <context>
    The receiver must target REAL topics and verify authenticity with the REAL mechanism. The
    read-capability matrix flags Webhooks V2 as a separate base URL (api.acculynx.com/webhooks/v2),
    3 read ops, possibly account-tier gated. Verify live (sandbox key): GET /webhooks/v2/topics for
    the topic list (looking for a job-created topic + field-changed topics such as
    job.financials.approved-value_changed and job.representatives.company_assigned per D-17), and
    determine how AccuLynx signs/authenticates delivered webhook payloads (HMAC signature header vs
    a shared secret vs a per-subscription token) from the docs + a POST /webhooks/v2/subscriptions
    test-event in sandbox. Do NOT create a prod subscription here — this is read/verify only.
  </context>
  <options>
    <option id="signature-hmac">
      <name>AccuLynx signs payloads with an HMAC header</name>
      <pros>Strongest: receiver verifies the signature against a shared signing secret; replay-protectable via timestamp.</pros>
      <cons>Requires capturing the signing secret at subscription time and a constant-time compare in the receiver.</cons>
    </option>
    <option id="shared-secret-path">
      <name>AccuLynx has no signature; use a shared-secret in the consumer URL/header</name>
      <pros>Simple: the subscription consumer URL carries an unguessable secret path/token the receiver checks.</pros>
      <cons>Weaker than HMAC (no per-payload integrity); mitigate with HTTPS-only + a long random token + rate limiting.</cons>
    </option>
  </options>
  <resume-signal>Report the live GET /webhooks/v2/topics result (the actual topic names) and the confirmed auth mechanism, then select: signature-hmac or shared-secret-path.</resume-signal>
</task>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet -> acculynx-webhook | A NEW public-facing endpoint receiving untrusted external POST payloads — the primary attack surface added by this plan. |
| webhook payload -> pull enqueue | An untrusted body decides which job gets pulled; must not let an attacker drive arbitrary/expensive pulls. |
| receiver -> AccuLynx subscription (prod write) | Creating a prod subscription is an external WRITE requiring human approval. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-08-01 | Spoofing | forged webhook POST | critical | mitigate | Verify authenticity (HMAC signature constant-time compare OR shared-secret token) BEFORE any action; unverified requests are logged signature_verified=false and rejected 401 with no pull enqueued. Verified live against AccuLynx's actual mechanism. |
| T-07-08-02 | Tampering | untrusted payload interpreted as instructions | high | mitigate | Body treated strictly as DATA (REQ-09/D-10): fields read positionally; no eval/exec path (grep-asserted == 0); payload stored in jsonb for audit, never executed. |
| T-07-08-03 | Denial of Service | replay / retry-storm / pull amplification | high | mitigate | Receiver returns 200 fast and enqueues (no inline full pull); replay handling via timestamp/nonce where the mechanism supports it; pull enqueue is scoped to the payload's job_id + account, so a forged/duplicated event cannot fan out beyond one job; rate-limited public endpoint. |
| T-07-08-04 | Information Disclosure | acculynx_webhook_events payload (PII) | high | mitigate | Deny-by-default RLS (mig 187, service_role only); secrets from Deno.env only (hard rule 2). |
| T-07-08-05 | Elevation of Privilege | prod subscription created autonomously | high | mitigate | POST /webhooks/v2/subscriptions is a blocking-human checkpoint, not auto-approvable — sandbox-proven first, human-fired against prod (D-17 write gate). |
| T-07-08-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new package installs (Deno std + existing supabase-js) — no legitimacy gate needed. |
</threat_model>
