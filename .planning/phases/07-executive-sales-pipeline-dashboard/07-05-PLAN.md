<objective>
Fix the silent-failure data layer beneath the Executive dashboard: job-walk.ts currently spreads
raw camelCase AccuLynx bodies into snake_case Postgres tables (near-100% PostgREST rejection) and
swallows the failure with console.warn, so the sub-resource tables that feed margin/financial KPIs
are effectively empty and no alert ever fires. This plan rebuilds job-walk on the D-14
capture-first / map-second contract: archive every per-job GET to acculynx_raw first, then project
FROM that body through explicit snake_case mappers, and route any upsert failure into a counted,
alertable error table wired into check_acculynx_alerts(). It also replaces the inline
.update().eq() watermark advance with the shared advanceWatermark() upsert helper so no account
silently restarts its walk from scratch.

Purpose: Eliminates the root-cause defect class (VERIFICATION gaps 2 and the watermark half of
gap 4, plus the alert-visibility half of gap 2). This is the foundation Wave 6 builds crm_pipeline
restoration on — mappers and the raw archive must exist before financials can be mapped forward.
Output: migration 186 (applied to prod), lib/mappers.ts, a rewritten job-walk.ts, and a fifth
alert condition.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AccuLynx API -> edge function | External API responses (untrusted PII: names, addresses, financial amounts) cross into the brain; archived raw then mapped. |
| edge function (service-role) -> acculynx_* tables | Service-role writes bypass RLS; must not widen any grant. |
| acculynx_job_walk_errors -> check_acculynx_alerts() -> Slack | Error counts flow to a Slack post via pg_net; token from Vault only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-05-01 | Tampering | mapper output written to typed tables | medium | mitigate | Mappers whitelist only known snake_case columns; unknown API keys never become columns (only land in the immutable `raw` jsonb) — prevents malformed/injected API fields from reaching typed schema. |
| T-07-05-02 | Information Disclosure | acculynx_job_walk_errors (may contain PII in error_message) | high | mitigate | Table is deny-by-default RLS (revoke anon/authenticated, grant service_role only), matching mig 177. error_message stores the PostgREST error, not row PII; do not log full row bodies. |
| T-07-05-03 | Denial of Service | check_acculynx_alerts() fifth condition | low | accept | The count query is indexed (partial index on resolved_at is null) and runs every 15 min; negligible load. |
| T-07-05-04 | Repudiation | silent write failures (the pre-existing defect) | high | mitigate | Replacing console.warn with counted acculynx_job_walk_errors rows makes every failure durable, queryable, and alertable — eliminates the silent-failure vulnerability the phase's failure was rooted in. |
| T-07-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new package installs in this plan (Deno std only, existing deps) — no legitimacy gate needed. |
