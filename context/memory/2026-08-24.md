**Decisions / lessons**:
- **I shipped a performance regression and caught it in verification.** 268's four-way
  OR had a non-indexable prefix disjunct; one such disjunct disqualifies the whole OR
  from a BitmapOr, so the planner abandoned `idx_abc_pli_desc_trgm` — full view scan
  8.6s → **19.9s**. A GIN index on `num_tokens` made it worse (907 candidate rows per
  loop vs trigram's 18). **271** cut the JOIN to two indexable disjuncts and dropped
  the index → 8.8s, plan `BitmapAnd(agreement, BitmapOr(trgm, color_key))`.
  Cost of the correction: 29 lines / $523.48, all ungated sub-0.45 prefix matches that
  were never part of the approved change.
  → **Invariant: a matcher change is not verified by its match counts. EXPLAIN the
  predicate before shipping a join over a large input.**
- **Invoice Audit page has never been rendering.** HTTP 200 + `{"offices":[],...}` +
  "Supabase pending". `authenticator` has `statement_timeout=8s`; `service_role` sets
  no override and inherits it; the view costs 8.8s; `fetchAll` paginates it. Proved it
  predates today with a probe view of the pre-session ABC arm: **8.60s vs 8.84s** —
  today's work is +0.24s (2.8%). Filed **PEC-241** (Urgent).
- Every claim the guard removed was hand-checked: 12" vs 9" Cobra, Rigid Vent 3 vs
  Ridge Vent 9, VC57 vs VC35, Winterguard Long 3x65 2SQ vs Short 3x32.5 1SQ. Three
  borderline false negatives (~$65) go with them — correct side to err on.
- `renewal_mode` defaults to `evergreen` on evidence, not caution: all 5 ABC lines
  priced in the last 7 days bill at **0.00%** against the June-expired book.

**Decisions**:

  30s instead of failing at 8 — a worse failure mode than the one it hides. Made the
  query fast instead.
- `v_invoice_audit_line` stays the definition of record; `silo_assertions()` still
  reads it under pg_cron (no ceiling), so nightly invariants test the live derivation.
- **PEC-243 root cause was the same 8s ceiling**, not a separate bug: `.eq(invoice_number)`
  isn't pushed into the LATERAL, and the cascade view materialised all 6,982 rows to
  join 15 (`Rows Removed by Join Filter: 104,715`).
- **Chris's ruling: a price list stays in effect until a NEW list supersedes it.**
  `expiry_date` is documentary. Confirms mig 270's `renewal_mode='evergreen'` default —
  no code change. Recorded docs/105 §6b + CONVENTIONS §10b + AGENTS + .cursor.
- **Flagged for the price-list builder (lands this week):** supersession is per agreement
  *version*, not per item — a new list retires the old wholesale, so items the new list
  omits go unpriced. And the builder's save path should fire
  `REFRESH MATERIALIZED VIEW CONCURRENTLY mv_invoice_audit_line` or the operator stares
  at unchanged numbers for up to 15 min.

**New invariant**: never read a per-row-LATERAL view through PostgREST — the 8s
`statement_timeout` on `authenticator` is inherited by `service_role`, so the service
key buys no relief. Materialise and read the matview.
