# Site audit — cc.proexteriorsus.net (2026-08-18)

Full work-surface audit: 38 page routes, 60 API routes, 13 client scripts.
Method: static analysis of the whole tree + live exercise of every route on the
dev server reading the **prod** database + browser network/console inspection.
Linear: **PEC-215** (data integrity), **PEC-216** (performance), **PEC-217** (hygiene).

## What is genuinely broken

### 1. Phantom $59,639 invoice row — PEC-215 (Urgent)
`abc_invoices` holds a row with blank `invoice_number`/`invoice_id`, NULL date,
`total_amount` **$59,639.20**, `source_endpoint = abc_csv_history` — a CSV
totals/footer line ingested as an invoice.

* Overstates ABC spend: **$2,257,064.14 reported vs $2,197,424.94 real (+2.7%)**
* Reaches `v_invoice_audit_invoice` and `v_invoice_acculynx_match`, so
  `invoice-audit-tree.ts:539` fires `/api/invoice-audit/invoice?invoiceNumber=`
  → **404 on every Invoice Audit page load** (confirmed in the network log)
* Migration 230 already works around it (`invoice_number <> ''`) but the row is live

### 2. Price Agreements page: 13.5 s / 3.8 MB — PEC-216 (Urgent)
`loadPriceAgreementManagement` paginates **`v_branch_item_api_price` in full —
39,984 rows, ~40 round-trips** — on every load, to serve a lookup consulted for
only **593** gap items (**1.5% utilisation**), then renders 3.77 MB of HTML.

1. **3 orphaned pages** — `vendor-regions`, `price-list/catalog`,

## What is healthy (verified, not assumed)

* **No hardcoded numbers reach users.** Zero literal `$` amounts and zero literal
  percentages in any page or component markup. Every KPI traces to a loader that
  queries Supabase. The one historical offender (`vendor-regions` demo panel with a
  hardcoded 2026-06-17 clock) was already removed 2026-08-05 and is documented.
* **Honest empty states.** `price-list/catalog` explicitly documents "No sample
  fallback — when the live loader returns nothing we render an honest empty state."
  This is the pattern to keep.
* **Link integrity is clean** — all 48 internal links and fetch targets resolve.
* **Design consistency is strong.** 36/38 pages use `AppShell`; department
  index/detail pages delegate to `DepartmentHome`/`DepartmentDetail`, which also use
  it. The 6 redirect stubs are documented retirements. `auth/denied` and
  `submit-agreement/[token]` are deliberate, documented standalones.
* Retirements are done properly — 301 redirect + a comment naming the superseding
  surface and the doc reference.

## Daily automated review — proposed stack

Today: Sentry is wired (client + server, `tracesSampleRate: 1.0`, session replay
0.1). **There are no CI workflows at all** (`.github/workflows/` is empty) — so
nothing runs on a schedule and nothing gates a deploy. That is the single biggest
structural gap.

### Layer 1 — Sentry (already installed; needs tuning)
* Add **release + commit tracking** so every error maps to a deploy SHA (the
  `/healthz` buildCommit already exists — feed it as the release).
* Upload **source maps** on build so stack traces are readable.
* Add **uptime/cron monitors** for the nightly jobs (ABC sync, `refresh_wip_ar_master`,
  pack publish) — silent job failure is currently invisible.
* Alert routing to `#pe-cc-dev-team` per the standing Slack rule.

### Layer 2 — synthetic daily sweep (new, highest value, cheapest)
A scheduled GitHub Action that reproduces exactly what this audit did:
* hit every route, assert **200 + no 404/500 in the network log**
* assert **response time budgets** (fail if a route regresses past its budget)
* assert **zero console errors**
* run the "no fabricated data" greps (literal `$`/`%` in markup, `mock|sample|hardcod`)
* run the link-graph validator (48/48 must resolve)
* open a Linear issue automatically on failure

Everything above is already scripted in this audit — it is a matter of committing
the checks and scheduling them.

### Layer 3 — Latitude.io
Prompt/agent observability for the Maya/Alex agent surfaces: log every agent run
with inputs/outputs, evaluate against a rubric, and catch quality regressions that
Sentry cannot see (an agent that succeeds technically but decides wrongly). Highest
value pointed at the accounting-intake classifier and Alex's No-Price triage, where
a silent behavioural drift has direct financial consequence.

### Layer 4 — Devin
Best used on the **backlog produced by layers 1–3**, not as a free-running reviewer:
hand it well-specified, verifiable issues (e.g. PEC-216's chunked `.in()` fix) with
the existing test suite as the gate. Keep the human explain-then-ship contract.

### Sequencing recommendation
1. Fix PEC-215 and PEC-216 (real defects, both well-specified).
2. Stand up Layer 2 — it is the cheapest and would have caught both automatically.
3. Tune Sentry releases/source maps/cron monitors (Layer 1).
4. Then evaluate Latitude and Devin against a backlog that is already clean.

**Security note:** a code-vulnerability scan was **not** part of this pass. Dependency
CVE scanning and a secrets/permission review should be their own audit — see the
`/security-review` skill and hard rules 2 and 12.
