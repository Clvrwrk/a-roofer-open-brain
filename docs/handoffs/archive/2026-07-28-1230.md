## Decisions Made This Session

- **Supabase is source of truth; every JT write staged in `jt_mirror.pending_write` first** — auditable, resumable, idempotent; do not bypass
- **No JT seats ever** — sales reps / 406 users are custom-field dropdown values, not users; encoded in every spec
- **Sandbox branch excluded, archived jobs excluded** from mirror scope (test noise); reversible via B2 re-stage if wanted
- **Duplicate AccuLynx contact names become suffixed JT accounts** (`suffixIfNecessary:true`) — faithful to source records, no conflation
- **Job-number collisions get `~<guid-prefix>` suffixes** (814 jobs) — true AccuLynx number preserved in `AccuLynx Job #` custom field
- **Same account+address = same JT location** — crosswalk-aliased; JT's own uniqueness rule guarantees identity
- **Vendors sourced from QBO register activity, not AccuLynx** — AccuLynx has no vendor contact typing (proven negative)

### Architecture decisions
- `$ref`/crosswalk convention: staged payloads carry `{"$ref": "<source_type>:<id>"}`; executor resolves TYPED BY TARGET FIELD (jobId→job, unitId→unit) — same source UUID can map to multiple jt_types
- Executor invariants: canary-first, ≤4 req/s, per-write checkpointing, 10-consecutive-failure halt, closed-job reopen→write→re-close, never leave a job reopened
- All checks are EXECUTED validators (live SQL / live Pave read-back), never file-existence tests

### Key invariants (never violate)
- **No JT user/membership/invite creation** — single-seat rule
- **No unstaged JT writes** — everything through pending_write
- **`notify` never true** on any payload (customer-facing notification safety)
- **JT hard limits:** job name ≤30 chars, externalId ≤32, customer names unique (use suffixIfNecessary), job numbers unique, (account,address) locations unique, customerOrder doc names ∈ {Proposal, Selections, Change Order}, closed jobs block writes

### JobTread API learnings (durable)
- Schema introspection: `POST https://api.jobtread.com/pave` `{"query":{"schema":{}}}` — full 189-type schema, no auth; saved as `pave-schema.json`
- Input unions discriminate on `"_type"` constants (e.g. lineItems elements = bare objects + `"_type":"costItem"`), NOT wrapper keys
- Update ops: all inputs under `"$"`; create-op response selection key is `created<Entity>`
- AccuLynx: API partitioned per branch key (9 `PE_CC_*` keys; default key sees almost nothing) — route by `account_key`
