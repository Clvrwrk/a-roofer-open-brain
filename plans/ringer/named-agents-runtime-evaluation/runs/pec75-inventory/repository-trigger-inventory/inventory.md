## Conflicts and Unknowns

1. **No singular cadence authority.** Five repository surfaces plus possible remote Hermes stores can disagree. Some generator output is enabled-by-construction while historical runtime evidence says jobs were paused.
2. **No singular Slack authority.** Command Center can start a shared Socket runtime, while the VPS status document claims eight listeners. Starting both can duplicate reads, Hermes calls, replies, and Linear effects.
3. **Identity behavior disagrees.** The runtime router refuses cross-agent fallback; the application poster silently uses the shared bot. A successful delivery can therefore be attributed to the wrong persona.
4. **Live claims are time-bound.** The June VPS/Kasm documents are **stale** for a July 26 decision. PEC-75 currently observes only Maya's Orgo resource; Slack token/socket health is operator-unverified and agent VPS health is **unknown**.
5. **Email is not closed loop.** AgentMail receipt logging does not create named-agent work, and the production 30-minute Google mailbox contract has no implemented canonical scheduler in the inspected repository.
6. **Health can be falsely reassuring.** `/healthz` can be green while every agent trigger is stopped, duplicated, stale-owned, or unauthenticated; dashboard agent health is mock data.
7. **Architecture eras overlap.** Kasm persistent profiles, headless VPS Hermes, Command Center Slack, and dedicated Orgo/Hermes all appear in the tree. The approved target is Orgo/Hermes, but old trigger paths are not evidenced as fenced off.
8. **Ownership declarations are split.** Department charters, named persona YAML, Slack registry, router registry, cadence YAML, and inbox roster are related but not mechanically reconciled.
9. **Current external state remains unknown by design.** This review did not access Slack, email, Google, Linear, Orgo beyond supplied sanitized evidence, VPS, Kasm, databases, health URLs, or secret stores. No secrets were read or reproduced.

## Freeze and Fencing

Fail closed from PEC-75 through the PEC-76 gate:

1. **Global freeze:** keep every named-agent mailbox job, Hermes cron, Slack listener, event handoff, and outbound effect disabled or paused. Do not infer “off” from missing health; require positive disable receipts from each possible authority during an authorized later phase.
2. **Inventory fence:** enumerate, without revealing credentials, every installed systemd unit, process/listener, Hermes `cron/jobs.json` or state database, Command Center deployment, Orgo computer, Kasm profile/session, webhook subscription, and provider scheduler. Match each to a stable persona/resource ID.
3. **Election fence:** choose one runtime owner per persona and trigger class. For the approved target, that is the persona's dedicated Orgo/Hermes runtime; Command Center remains system ingress/source of truth and must not concurrently own the same Slack or schedule occurrence.
4. **Generation fence:** issue a monotonically increasing ownership generation and fenced lease for `(persona, trigger_class)`. A stale generation may read nothing and produce no effect. Lease loss aborts before model invocation or delivery.
5. **Occurrence fence:** one canonical cadence registry generates an idempotency key for each scheduled occurrence. Mail uses stable message/thread IDs; Slack uses workspace/event identifiers; queue events use immutable work-item/event IDs. Reconcile uncertain remote outcomes before retry.
6. **Identity fence:** dedicated persona credentials and homes only. Missing identity, token, mailbox principal, Orgo scope, or Command Center subject is a hard failure. Named Slack posts may never fall back to a shared bot.
7. **Effect fence:** default all writes/sends to draft/propose. Allow only the separately approved Christopher destination during the initial phase, with destination allowlist, approval state, receipt, kill switch, and no reply to the original sender.
8. **Plane fence:** DevTeam/Open Engine triggers and Roofing-Ops named-agent triggers use separate queues, credentials, leases, channels, and issue semantics. Neither may silently consume the other's work.
9. **Health fence:** health is green only when runtime identity, lease generation, Slack socket, cron store, mailbox cursor, Orgo computer, Google session, Command Center connectivity, last/next run, queue depth, budget breaker, and kill switch are all current. Unknown becomes degraded/blocked, never green.
10. **Activation sequence:** Maya only, synthetic/redacted inputs, one trigger class at a time, duplicate and stale-owner tests first, then three clean observed days and Christopher Hussey's durable go/no-go. Stop on any identity mismatch, duplicate, ambiguous ownership, missing receipt, falsely green health, or unreconciled effect.
